## 📌 核心问题

**"机器如何更好地理解我们的情境和目的？"**

当前对上下文工程的理解过于狭隘：
- 常被视为 Agent 时代的新创新
- "上下文"常被狭义定义为对话历史、系统提示
- 忽视了 20 多年的发展历史

**论文主张**: 上下文工程实践可追溯至 20 多年前，需要从更广阔的历史视角理解其发展。

---

## 🔑 核心定义

### 上下文 (Context)
> "上下文是可用于刻画与用户 - 应用交互相关的实体情境的任何信息"

形式化定义：
```
C = [relChar(e) for e in E_rel]
```
其中 `E_rel` 是与交互相关的实体集合。

### 上下文工程 (Context Engineering)
> 系统地设计和优化上下文的**收集、存储、管理和使用**，以增强机器理解和任务性能。

形式化定义：
```
CE: (C, T) → f_context
```
其中 `C` 是原始上下文，`T` 是目标任务，`f_context` 是上下文处理函数。

## 📊 四阶段演进模型

| 阶段 | 时期 | 智能水平 | 上下文角色 | 人机交互成本 |
|------|------|----------|------------|--------------|
| **1.0** | 1990s-2020 | 原始计算 | 上下文即翻译 | 高 |
| **2.0** | 2020-至今 | Agent 中心智能 | 上下文即指令 | 中 |
| **3.0** | 未来 | 人类水平智能 | 上下文即场景 | 低 |
| **4.0** | 推测 | 超人智能 | 上下文即世界 | 极低 |

**核心洞察**: 更多智能 → 更多上下文处理能力 → 更低人机交互成本

## 🏗️ Era 1.0 vs Era 2.0 对比

| 维度 | 1.0 (1990s-2020) | 2.0 (2020-至今) |
|------|------------------|-----------------|
| **技术背景** | 普适计算、上下文感知系统 | 大语言模型、Agent |
| **典型系统** | Context Toolkit, Cooltown | Claude Code, Langchain, Cursor |
| **核心机制** | 传感器融合、规则触发 | Prompting, RAG, CoT, 记忆 Agent |
| **上下文容忍度** | 低 (需结构化输入) | 高 (可处理自然语言) |
| **类人程度** | 低 | 相对较高 |

### 1.0 时代核心实践

**Context Toolkit 框架** (Anind Dey, 2001):
- **Context Widgets**: 封装传感器，提供标准化接口
- **Interpreters**: 从原始数据推导高层含义
- **Aggregators**: 整合多个上下文源
- **Services**: 提供应用级上下文功能
- **Discoverers**: 动态注册和发现上下文组件

**局限性**:
- 机器只能执行预定义逻辑
- 无法理解自然语言语义
- 需要设计师作为"意图翻译者"

### 2.0 时代核心进步

**1. 上下文获取**: 高级传感器
- 智能手机、可穿戴设备、环境设备
- 多模态信号：文本、图像、音频、位置、触摸、眼动、脑电波

**2. 原始上下文容忍度**: 从结构化输入到人类原生信号
- 1.0: GPS 坐标、时间、预定义状态
- 2.0: 自由文本、图像、视频 (高熵信息)

**3. 上下文理解**: 从被动感知到主动协作
- 1.0: 条件 - 动作规则 ("如果在办公室，则静音手机")
- 2.0: 主动理解用户行为并协作 ("分析写作意图，建议下一节内容")

## 📦 上下文收集与存储

### 设计原则

1. **最小充分性原则**: 只收集任务必需的信息
   - 上下文价值在于充分性，而非数量

2. **语义连续性原则**: 保持意义的连续性，而非数据的连续性

### 存储架构

**分层存储策略**:

| 存储层 | 用途 | 技术示例 |
|--------|------|----------|
| **短期缓存** | 快速访问、临时状态 | 内存缓存、边缘节点 |
| **中期存储** | 活动记录、用户偏好 | SQLite, LevelDB, RocksDB |
| **长期持久化** | 跨设备同步、全局知识 | 云平台、远程服务器 |
| **安全存储** | 敏感信息 | OS 安全存储、硬件安全模块 |

**Claude Code 实践**:
- 维护结构化笔记
- 定期将关键信息写出上下文窗口到外部记忆
- 支持长周期任务 (如数千步的 Pokemon 游戏) 中断后无缝恢复

## 🧠 上下文管理

### 文本上下文处理策略

| 方法 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **时间戳标记** | 附加时间戳保留顺序 | 简单、低维护成本 | 无语义结构、扩展性差 |
| **功能/语义标签** | 按角色标记 (目标、决策、行动) | 易于解释和检索 | 略显僵化 |
| **QA 对压缩** | 重构为问答对 | 检索高效 | 破坏原始思路流 |
| **分层笔记** | 树状结构组织 | 清晰呈现 | 不捕捉逻辑关系 |

### 多模态上下文处理

**1. 映射到共享向量空间**
- 各模态独立编码 → 投影到固定维度共享空间
- 语义相关内容在空间中靠近

**2. 自注意力融合**
- 文本和视觉 token 在每一层相互关注
- 捕捉细粒度跨模态对应 (如"哪个短语指向图像哪个区域")

**3. 交叉注意力**
- 一个模态作为 Query，另一个作为 Key/Value
- 针对性跨模态检索

### 分层记忆架构

**定义**:
- **短期记忆**: `Ms = f_short(c ∈ C : w_temporal(c) > θs)`
- **长期记忆**: `Ml = f_long(c ∈ C : w_importance(c) > θl ∧ w_temporal(c) ≤ θs)`
- **记忆转移**: 频繁访问或高重要性信息从短期巩固到长期

**自烘焙 (Self-Baking)**:
> Agent 选择性地将自身上下文"消化"为持久知识结构

- 原始上下文 → 自然语言摘要
- 原始上下文 → 固定 Schema 关键事实
- 逐步压缩为意义向量 (嵌入)

**示例**:
- **CodeRabbit**: 构建结构化案例文件，编码跨文件依赖、历史 PR 信息
- **H-MEM**: 将上下文转化为意义向量，支持层次化记忆

## 🔄 上下文使用

### 系统内上下文共享

| 模式 | 描述 | 示例系统 |
|------|------|----------|
| **嵌入提示** | 直接将上下文放入下一 Agent 的输入提示 | AutoGPT, ChatDev |
| **结构化消息** | 使用固定格式交换消息 (任务类型、输入、输出、推理步骤) | Letta, MemOS |
| **共享记忆** | 通过共享记忆空间间接通信 (读写记忆块) | MemGPT, A-MEM |

**子 Agent 策略**:
- 每个子 Agent 有独立的上下文窗口、系统提示、工具权限
- 功能隔离 (分析、执行、验证) 或层次隔离 (规划、实现、审查)
- 减少上下文污染风险

### 跨系统上下文共享

**挑战**: 不同系统使用不同格式、结构、逻辑

**解决方案**:

| 方法 | 描述 | 优缺点 |
|------|------|--------|
| **适配器转换** | 为每个连接构建转换器 | 灵活但需大量适配器 |
| **共享表示** | 所有系统使用统一表示 | 简化集成但需协调 |
| **共享数据格式** | JSON Schema 或 API | 精确但需严格协调 |
| **自然语言摘要** | 交换简短描述 | 灵活但解析困难 |
| **语义向量** | 数字向量表示意义 | 紧凑通用但不可解释 |

### 上下文选择

**核心问题**: 在可用上下文中，应选择哪个子集用于当前步骤？

**策略**:
- 基于时间相关性权重
- 基于重要性权重
- 基于任务相关性过滤
- 主动推断用户需求

## 🎯 应用场景

### 1. CLI (命令行界面)
- **SII-CLI**: 下一代认知 Agent 智能生态系统
- 上下文感知命令补全、历史命令推理

### 2. 深度研究
- **LeadResearcher**: 处理超长上下文 (>200k tokens)
- 将研究计划存入持久记忆，防止关键信息丢失
- 子 Agent 并行工作，LeadResearcher 总结并决策下一步

### 3. 脑机接口
- 神经信号、情感状态作为上下文
- 自适应神经形态解码器

## 🚀 未来方向

### Era 3.0: 人类水平智能
- 触觉、嗅觉、味觉信息整合
- 理解语调、停顿、眼神接触、沉默
- 统一为长期**个人数字记忆**
- 类人"遗忘"和"回忆"能力

### Era 4.0: 超人智能 (推测)
- "上帝视角"理解人类意图
- 主动为人类构建新上下文
- 揭示未明确表达的需求
- 机器成为洞察和灵感来源

**示例**: 围棋职业选手从 AI 学习超人策略
